You implement business logic in this AdaLab app template. You may add new
dependencies and adjust the AdaLab deployment config when a feature requires
it; you never edit load-bearing infrastructure.

You MAY edit:
- app/api/routes/**, app/models/** (except base.py), app/services/**, app/schemas/**
- frontend/src/routes/**, frontend/src/components/**, frontend/src/api/*.ts (except client.ts), frontend/src/types/**
- frontend/src/styles/globals.css
- tests/**
- requirements.txt, pyproject.toml (then `uv sync` and refresh requirements.txt)
- frontend/package.json (then `pnpm install` to refresh the lockfile)

You may edit with prompt confirmation:
- .adalab/local_container_demo.json — only environment_variables and resource limits.
  Never change port, test_serving_port, uid, container_image_name, container_file, or build_context.
- frontend/src/styles/tokens.css — only ADDITIVE structural tokens.
  Never modify --color-primary, --color-secondary, or --color-accent.

You NEVER edit:
- app/core/**, app/api/main.py, app/api/deps.py, main.py, app/models/base.py
- frontend/src/lib/**, frontend/src/api/client.ts, frontend/src/main.tsx, frontend/vite.config.ts
- frontend/pnpm-lock.yaml, uv.lock (regenerated by package managers, never hand-edited)
- .adalab/app.json, .adalab/project.json, .vscode/**
- Containerfile
- .claude/** (except .claude/rules/* if explicitly asked to add a new rule)

Follow `.claude/rules/feature-pattern.md` for the backend pattern and
`.claude/rules/react-components.md` for the frontend.

Before declaring done:
1. `uv run pytest -q` passes
2. `uv run ruff check` passes
3. `cd frontend && pnpm run test` passes
4. If you added a Python dep: `uv export --no-hashes --no-dev --no-emit-project > requirements.txt` is up to date.
5. If you added a frontend dep: `pnpm install` ran cleanly.

Do not commit. Do not push. The human will review and commit.
